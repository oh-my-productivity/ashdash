# Ashdash 0.1.0

First release candidate of **Ashdash**, a keyboard launcher for macOS written in Rust: press a hotkey (default Option+Shift+Space), type, press Return.
"Ashdash" is a **working name** and may change before a stable release.

> **Read this first.** This build is signed *ad hoc* and is **not notarized** (there is no Apple Developer ID behind it yet), so macOS Gatekeeper blocks it the first time. See [Install](#install-an-ad-hoc-build).
> Statements below marked **unverified** describe behaviour that has code and tests but that nobody has been able to confirm on a real desktop or a clean machine.

## What is in

- **Launcher**: apps (persistent index kept fresh by FSEvents, initials and word-prefix matching, learned ranking you can switch off and wipe), calculator, keyword web searches (`g rust`), system commands
  (destructive ones ask first), path browsing (`~/Doc`), run in Terminal (`> cmd`).
- **Files and data**: file search through Spotlight (`open`, `find`, `in`, `kind:pdf`), browser bookmarks (`bm`), clipboard history with images and file lists (`clip`), snippets with placeholders (`snip`), auto-paste.
- **Universal Actions** (Right Arrow on a result, `actions`), file buffer (Option+Up/Down), Quick Look, Large Type, `.alfredappearance` themes.
- **Preferences window** (`ashdash prefs`, or `ashdash://prefs`, or the menu-bar item) with live reload of `config.json`, workflows and snippets.
- **Reference-compatible workflows**: keyword and Script Filter inputs (JSON and XML, `cache`, `rerun`), list and file filters, scripts, conditionals and other utilities, Open URL/File, Write File, Terminal,
  notifications, clipboard, Large Type, external triggers and workflow hotkeys. Per-object-type compatibility and the trust model: [docs/WORKFLOWS.md](../WORKFLOWS.md).
  **Every import first shows what the workflow can do and asks**; the file you previewed is the file that gets installed.
- **Automation**: the `ashdash` command line (`query`, `run`, `import`, `workflows`, `trigger`, `show`, `search`, `reload`, `config`, `login-item`, ...), the `ashdash://` URL scheme, an AppleScript dictionary, launch at login. See [docs/AUTOMATION.md](../AUTOMATION.md).
- **Performance** (measured on an M3 Pro with synthetic data, see [docs/PERF.md](../PERF.md)): engine query p95 about 0.4 ms at 5,000 apps (target 10 ms); start with a warm index cache 5-8 ms to first answer; clipboard search 0.3 ms at the default
  200 entries. Window start-up time and the real process's idle memory were **not measured** (they need the GUI).

## What is not in

Contacts and dictionary lookup, System Settings panes, history search, system-wide snippet expansion (needs an event tap), music control, a workflow editor, sync. Workflow trigger kinds that the reference launcher has and Ashdash does not
implement are listed in [docs/WORKFLOWS.md](../WORKFLOWS.md). Trust-prompt extras (a diff when a workflow is replaced, imports disabled until enabled, ownership checks for `workflow_dirs`) are planned, not done
([docs/SECURITY.md](../SECURITY.md) section 3).

## Install (an ad-hoc build)

Requirements: macOS 12 or newer (**unverified** on 12 and 13; the author's machine runs macOS 26). Apple Silicon and Intel are both in the universal build.

1. Download `Ashdash-0.1.0.dmg` and `Ashdash-0.1.0.dmg.sha256` from the release page. Check the download: `cd ~/Downloads && shasum -a 256 -c Ashdash-0.1.0.dmg.sha256` should print `OK`.
2. Open the DMG and drag **Ashdash** to **Applications**.
3. The first launch is blocked by Gatekeeper ("cannot be opened because the developer cannot be verified" / "Apple could not verify..."). Do **one** of these:
   - on **macOS 15 and later** (verified on 15.7 in a VM): the dialog offers only *Done* and *Move to Trash*. Click *Done*, open System Settings > Privacy & Security, press **Open Anyway** next to "Ashdash was blocked to protect your Mac" (macOS asks for your password), then open Ashdash again and press **Open Anyway** in the second dialog; or
   - in Terminal, any macOS: `xattr -dr com.apple.quarantine /Applications/Ashdash.app`, then open it normally; or
   - on macOS 14 and earlier: right-click **Ashdash** in Applications, choose **Open**, then **Open** again in the dialog (Apple's route there; not tested by the project).
   macOS 26 is **unverified**.
4. Press **Option+Shift+Space**. Ashdash lives in the menu bar and has no Dock icon. `Esc` closes the window, `Cmd+Q` quits.
5. Permissions are requested only when a feature needs them (Accessibility for auto-paste, Automation for system commands and Terminal, Full Disk Access for Safari bookmarks); see [docs/USER_GUIDE.md](../USER_GUIDE.md) section 3.

You can verify the signature type yourself: `codesign -dv /Applications/Ashdash.app` shows `Signature=adhoc`. Uninstall: quit Ashdash, delete the app, and delete `~/Library/Application Support/ashdash` and `~/Library/Caches/ashdash`.
`brew install --cask` is **not available** (no tap is published).

Building from source: `cargo run -p ashdash --release`, or `packaging/build-app.sh` and `packaging/make-dmg.sh` ([docs/RELEASING.md](../RELEASING.md)).

## Living next to the reference launcher

Ashdash is designed to coexist with a real reference launcher installation: its own data folder (`~/Library/Application Support/ashdash`), its own bundle id (`dev.ashdash.launcher`), its own URL scheme (`ashdash://`; it never registers `reference://`), and
a different default hotkey (Option+Shift+Space; the reference launcher's default is Option+Space). It registers for `.alfredworkflow`, `.alfredappearance` and `.alfredsnippets` files only as an *alternate* handler, so double-clicking such a file keeps
opening the reference launcher; use Open With, `open -a Ashdash.app file.alfredworkflow`, or `ashdash import file.alfredworkflow`. Coexistence was designed and tested at the level of files and registrations; running both at once on a real desktop
for a longer time is **unverified**.

## Clean-room statement

Ashdash is an independent project, **not affiliated with, endorsed by or sponsored by its publisher or the reference launcher application**, and contains no reference launcher code or assets. It is *not* a strict two-team clean-room
implementation: the authors observed the reference launcher's behaviour, file formats and public documentation, wrote the code themselves, and copied nothing. The reference launcher's binary was never decompiled or instrumented. Interoperability
identifiers (file extensions, workflow `info.plist` keys, environment variable names, JSON field names) are reproduced on purpose so that existing workflows run. No lawyer has reviewed this. Details and the evidence:
[docs/CLEAN_ROOM.md](../CLEAN_ROOM.md), [docs/REVERSE_ENGINEERING.md](../REVERSE_ENGINEERING.md).

## Known issues

Verified problems:

- Workflows run arbitrary scripts with your permissions. The import prompt tells you what a workflow *can* do, but a Script Filter's results can change what later steps do, which no static summary can show.
  Import only workflows you trust. SEC-03, SEC-13 and SEC-14 in [docs/SECURITY.md](../SECURITY.md) stay open on purpose, to remain compatible with the reference launcher.
- Wave 3 left low-severity items that may still be open at this tag: hard links inside a workflow's folder are not detected (documented), config writers that bypass the lock (an editor, `jq`) are not coordinated and a save drops
  keys it does not know, a few helper programs are started by bare name, and the preferences drop zone accepts fewer file extensions than the launcher. [docs/STATUS.md](../STATUS.md) is the authoritative list; check
  [CHANGELOG.md](../../CHANGELOG.md) for which of them were fixed before this tag.
- Themes: a theme you install (Finder, `ashdash theme`, preferences) must be under 2 MiB; one already installed loads up to 8 MiB. If you ran a pre-release build that refused larger installed themes, they load again with this version (see [CHANGELOG.md](../../CHANGELOG.md)).
- The clipboard history is plain JSON (mode 0600) in your data folder. There is no setting to stop recording; limit it with `clipboard.max_entries`, `clipboard.max_age_days`, `clipboard.ignored_apps`, or wipe it with `clip clear all`.

**Unverified** (code and tests exist; nobody confirmed it on a real desktop or a clean machine):

- Real Cmd+V auto-paste, and the concealed-clipboard filter with a real password manager.
- Safari bookmarks under a real Full Disk Access denial; Arc and Firefox bookmark parsers on real profiles.
- Finder trash script execution (only a read-only contract test ran); AppleScript through JXA with a file path instead of the bundle id.
- The held-modifier subtitle swap, several monitors and full-screen apps, whether the launcher draws above Quick Look.
- The actions panel, the in-window import prompt with a held Return, every preferences page, live hotkey rebind and theme apply, file watching with real editors, `rerun` on screen, Large Type scrolling on screen.
- Notarization and a Gatekeeper-quarantined download on a clean Mac; the x86_64 slice on Intel hardware (it was run under Rosetta only); the real process's idle memory and window start-up time.
- A fresh-account install and first run (the manual checklist is [docs/QA.md](../QA.md) section 3).
